🛡️ 9-Layer Defense Integration

The MAYOTIX SELinux policy operates at Layer 4 of the defense-in-depth architecture, providing Mandatory Access Control that enforces strict boundaries between system components and limits the impact of potential security breaches.

1
Secure Boot
UEFI Secure Boot with Shim bootloader and GPG signing ensures only trusted code executes during boot
2
Early Boot Security
Dracut initramfs with LUKS2 encryption and Argon2i key derivation protects the boot process
3
Kernel Hardening
ASLR, stack protection, DEP/NX, SMEP, SMAP provide runtime memory protection
4
MAC (SELinux)
SELinux enforcing mode with custom MAYOTIX policies enforces strict access controls
5
Service Hardening
27+ systemd security directives per service provide process-level isolation
6
Filesystem Security
LUKS2 encrypted partitions with immutable root filesystem (Silverblue pattern)
7
Application Sandboxing
Flatpak containerization isolates user applications from the system
8
Audit & Logging
systemd-journald and auditd provide persistent security event logging
9
Secure Updates
Image-based atomic updates with GPG signing and reproducible builds

# Files

files_type(mayotix_lib_t)
files_type(mayotix_var_lib_t)
files_type(mayotix_etc_t)
files_type(mayotix_log_t)
files_type(mayotix_tmp_t)

########################################
#
# mayotix local policy
#
########################################

# Domain transitions
type_transition unconfined_t mayotix_exec_t:process mayotix_t;
type_transition init_t mayotix_exec_t:process mayotix_t;

# Execute permissions
allow mayotix_t mayotix_exec_t:file { execute execute_no_trans read open };
allow mayotix_t mayotix_lib_t:file { read open };

# Var/lib access
allow mayotix_t mayotix_var_lib_t:dir { search add_name remove_name create write };
allow mayotix_t mayotix_var_lib_t:file { create read write open unlink link rename };

# Etc access
allow mayotix_t mayotix_etc_t:dir { search };
allow mayotix_t mayotix_etc_t:file { read open };

# Log access
allow mayotix_t mayotix_log_t:dir { search add_name };
allow mayotix_t mayotix_log_t:file { create write open append };

# Tmp access
allow mayotix_t mayotix_tmp_t:dir { search add_name remove_name };
allow mayotix_t mayotix_tmp_t:file { create read write open unlink link rename };

# Basic permissions
allow mayotix_t self:capability { sys_admin sys_tty_config sys_resource };
allow mayotix_t self:process { siginh noatsecure rlimitinh setrlimit };
allow mayotix_t self:unix_stream_socket { create connectto };
allow mayotix_t self:unix_dgram_socket { create sendto };

# Network
allow mayotix_t self:tcp_socket { name_bind name_connect };
allow mayotix_t self:udp_socket { name_bind name_connect };

# Interface definitions for MAYOTIX SELinux policy

## <summary>
## Execute a mayotix domain transition and allow execution
## </summary>
## <param name="domain">
## <summary>
## Domain allowed access.
## </summary>
## </param>
interface(`mayotix_domtrans',`
    genre(usertype)
    typetrans_pattern($1, mayotix_exec_t, process, mayotix_t)
    allow $1 mayotix_exec_t:file { execute execute_no_trans read open };
    allow mayotix_t $1:process { siginh noatsecure rlimitinh setrlimit };
')

## <summary>
## Allow domain to read mayotix configuration files
## </summary>
interface(`mayotix_read_config',`
    genre(usertype)
    allow $1 mayotix_etc_t:dir search;
    allow $1 mayotix_etc_t:file { read open };
')

## <summary>
## Allow domain to read mayotix log files
## </summary>
interface(`mayotix_read_log',`
    genre(usertype)
    allow $1 mayotix_log_t:dir search;

⚙️ Enforcement Model

Policy Loading Flow

01 Compile .te → .mod using checkmodule
02 Package .mod → .pp with semodule_package
03 Load policy into kernel with semodule -i
04 Set SELinux to enforcing mode (setenforce 1)
05 Apply file contexts with restorecon
06 Verify enforcement with getenforce and avc logs

MAC Enforcement Principles

Default Deny: All operations are denied by default unless explicitly allowed by policy rules. This zero-trust approach ensures maximum security.

The MAYOTIX SELinux policy enforces strict type enforcement where:

  • Every process runs in a defined security context (domain)
  • Every file/object has a security type label
  • Access is only granted through explicit allow rules
  • Domain transitions are controlled and audited
  • File context mappings ensure proper labeling
